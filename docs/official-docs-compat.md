# Official Docs Compatibility

SKS keeps release-gated behavior tied to the **current stable** Codex dependency graph selected by `package.json`, a runtime-generated App Server v2 schema, official Codex multi-agent V2 / subagent configuration and hook lifecycle, Codex Desktop Browser/Chrome/Computer Use plugin surfaces, explicit image-model selection with `gpt-image-2.5-sunburst`, and OpenAI Structured Outputs.

Product docs must not treat a fixed `0.x.y` string as permanent SSOT. The exact SDK pin is release input only; feature support is decided through the resolved runtime and capability probes.

The compatibility report is generated by:

```bash
node ./dist/scripts/official-docs-compat-report.js
```

It writes report artifacts under `.sneakoscope/reports/` for the current package version.

The report records the current baselines used by release readiness:

- OpenAI Codex stable release baseline: the measured pin recorded by the report generator for this package
- Codex App Browser guide: `https://learn.chatgpt.com/docs/browser`
- Codex Chrome Extension guide: `https://learn.chatgpt.com/docs/chrome-extension`
- Codex Computer Use guide: `https://learn.chatgpt.com/docs/computer-use`
- Codex App image generation guide: `https://learn.chatgpt.com/docs/image-generation`
- OpenAI Image Generation guide: `https://developers.openai.com/api/docs/guides/image-generation`
- `gpt-image-2.5-sunburst` model guide: `https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst`
- OpenAI Structured Outputs guide: `https://developers.openai.com/api/docs/guides/structured-outputs`

Release-gated rules:

- Package, lockfile, runtime resolver, and runtime-generated App Server schema verify one current measured Codex graph; package/PATH/Menu Bar/marketplace disagreement is gate fail.
- Naruto uses the stable opt-in multi-agent V2 path (`features.multi_agent_v2`) with unified `[agents]` model/concurrency settings (wrap-only).
- Official `SubagentStart`/`SubagentStop` hook records are treated as lifecycle events. Because `SubagentStop` does not provide a trustworthy success field, SKS requires the parent to emit `sks.subagent-parent-summary.v1` with one structured outcome per thread and fails closed on ambiguity or failure text.
- App Server v2 proof covers native thread list/read/search and current-time handling against the schema generated by the resolved CLI during the gate. No version-named schema tree is shipped.
- Browser, Chrome, Computer Use, and image generation use native Codex Desktop plugins; Doctor may repair installation/feature state but must re-probe before claiming readiness. Agents never run `sks doctor --fix`.
- Full SKS image evidence requires the current model and completed output from the selected provider. See [Image generation](image-generation.md) for host restrictions and provenance.
- Web, browser, localhost, website, webapp, and web-based app verification uses the official Codex Chrome Extension path first; Computer Use is reserved for native Mac/non-web targets.
- Image skills consult the official catalog and the single shared model policy; prompt text alone does not select a model.
- The current API supports custom sizes, transparent PNG/WebP, and quality through `max`. The former automatic-fidelity claim is removed.
- UX/PPT generated-review routes must produce request/response artifacts, generated image artifacts, and strict structured issue ledgers before verified claims can pass.
- Structured extraction schemas use strict JSON schema behavior with `additionalProperties:false`.

If official Codex hook hashes are unavailable from the installed Codex CLI, SKS marks official discovery as integration-optional and enforces the managed-hooks path instead of writing SKS-only `trusted_hash` values.
